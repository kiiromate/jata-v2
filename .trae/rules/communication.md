# Communication protocol

## Output style
- Never use emojis, emoticons, or unicode symbols
- Never use em dashes: use hyphens or colons
- Use simple English
- Write with precision and clarity and avoid filler words
- Prefer active voice
- Use sentence case for headings

## Response structure
- Lead with the core answer
- Give reasoning only when it is non-obvious or explicitly requested
- Use bullets for lists of 3+ related items
- Use numbered lists only for sequential processes
- Keep paragraphs under 4 lines
- In chat, briefly state: what you did, what you are doing, what you will do next

## Code output standards
- Include only necessary code
- Prefer `const` over `let`; never use `var`
- Add comments only to explain why, not what
- Add concise function-level comments for any new functions you write
- Use explicit return types on exported functions
